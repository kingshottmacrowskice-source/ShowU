# ShowU 文件协议 v1（实现约定）

本文是实现约定，不是新增用户需求。需求事实源为 requirements.md。

一次性查找、解释或核对信息，直接答复，不登记模块需求、计划或任务，也不更新完成状态。若用户随后明确要求修改项目或长期遵守某项约定，只对新增的项目要求执行相应流程。

## 新会话如何接续

1. 读用户维护的 `.showu/brief.md`，理解目的与边界；AI 不能代写或补写该文件。
2. 读 `.showu/plans.md`，选择当前 active 计划；若有多个，结合用户指令选择，不默认全部执行。
3. 读该计划的任务、设计理由、验证证据、阻塞与下一步。
4. 读关联的 `.showu/requirements/<模块>.md`，再读相关代码，核对记录与实现是否一致。
5. 新计划按 S3 → S2 流程检查冲突；执行中用 S1 及时更新。记录过时则根据实际证据纠正，不能凭旧勾选宣称完成。

长时间开发的可靠性来自工具主动读取与维护这些文件；安装 SKILL 或创建目录并不能保证所有 AI 工具自动遵守。应在所用工具的项目指令入口引用本流程。仓库 AGENTS.md 已演示这一入口。

## 文件语法

- `.showu/config.json`：`{"schemaVersion":1}`。不放本机项目路径、启动命令或凭据。
- `.showu/plans.md`：Markdown 表格，列为计划标题、状态、任务文件链接；文件链接为 `plans/<slug>.md`。
- slug：小写英文字母或数字开头，可含 `-`，最长 64 字符。不能用路径或 Windows 保留文件名。
- 计划文件：一级标题；独立行 `status: active|paused|done|cancelled`；包含目的与来源、代码现状与冲突检查、任务、设计理由、验证与完成证据、下一步。
- 任务：`- [ ] T1 描述` 或 `- [x] T1 描述`。下一行可用两个空格缩进的 `status: doing|blocked|cancelled` 覆盖复选框状态。切回二态时删除覆盖行。
- 索引状态与计划文件状态应同时维护。软件的计划操作负责同步，外部 AI 修改后应自行核对。
- 模块需求：每项有稳定 ID、能力点、诉求、状态、操作、来源计划/任务；变更追加记录并把旧条目标为 superseded 或 deprecated，不能删掉历史。

## 需求与设计的边界

只有用户主动提出或确认的内容是需求。实现选型、方案权衡和未获确认的建议放在计划的设计理由中，不能冒充用户意图。每次重要设计记下日期、原因、受影响任务与替代方案；完成记录写实际运行的验证命令、结果及未验证的限制。

## 冲突检查

在创建计划前读取相关代码和同模块需求，逐条比较能力点与诉求。仅同模块或同能力点不构成冲突；三条件同时成立才停止任务。写出旧需求、拟议需求、冲突理由、来源和需要裁决的问题。用户裁决后保留历史与裁决记录，再恢复受影响工作。

软件要求创建者填写已读代码、涉及模块、需求来源与检查结论。这是留痕，不是自动语义冲突检测。若选择“有冲突”或“未检查”，不能创建执行计划。AI 创建仍必须遵守 S3，不能把界面声明当成检查替代品。

## 删除、保存与监听

删除计划移除索引项，任务文件移到 `.showu/plans/archive/`，保留需求中的来源和设计历史。删除不会删除模块需求。普通编辑允许用户修改 brief，界面有明确标识；AI 的权限仍为只读。

应用只访问选定项目的 `.showu`，拒绝路径穿越与符号链接。保存时比对原文，外部改动后要求重新加载或复制自己的草稿；不自动覆盖。监听检测到脏编辑器时只提示。计划和索引联合写入失败会回滚；进程断电仍需依赖 Git 恢复，第一版不宣称跨文件数据库事务。

## 启动器与 Git

启动命令是可执行程序及参数数组，`{project}` 替换为当前项目路径，不拼接 shell 命令。Windows `.lnk` 通过系统 ShellExecute 打开；组合各项独立启动并报告结果。配置仅由用户设置，项目 Markdown 不能触发执行。

链接操作对已有本地目录执行 git init（必要时）和添加/更新 origin，不执行 clone、不自动提交。检查更新先 fetch，再报告当前上游 ahead/behind；没有上游时如实提示。pull 使用 `--ff-only`；push 不强推；网络失败显示 Git 原始诊断。Git 使用本机现有凭据配置，应用不存凭据。

## 长期规模与分层

需求主文件仍是唯一事实源。有效需求不因超长被截断，历史移动保留原文、稳定 ID、替代关系和来源。brief 由用户维护，AI 不压缩。

- 模块顶部“代码入口”使用仓库相对路径及一句职责，通常 3–8 项；只存这一份，不列行号或全量需求/代码映射。入口随相关改动原位更新，未关联代码仍需检查依赖和影响。
- 有效需求、未裁决冲突及仍适用的裁决保留在当前模块。失效原文可放 requirements/history/<模块>/<年份>.md，当前文件保留追溯链接。历史子目录不计为需求模块。
- plans.md 是全部计划的总入口，可链接 plans/indexes/YYYY.md；每个计划只登记一次，任务正文仍在 plans/<slug>.md。分片内的计划可重开，保留所在索引以避免三文件迁移，应用合并索引后识别当前状态；AI 开始时也须搜索分片中的 active/paused 行，不能仅看主表。分层年份表示整理年份，不推测计划创建时间。
- 删除计划仍迁到 plans/archive，不等同于完成计划分层；原 slug 可在该目录追溯。
- 计划顶部保持一个当前摘要，旧过程可移 plans/history/<slug>/<年份>.md；保留重要设计理由、证据及来源链接，不保存完整聊天或冗长命令输出。
- 需求主文件仅将历史变更表分到 docs/history/requirements-YYYY.md，保留链接；有效需求仍在主文件。
- 软阈值：需求/协议 300 行或 24 KiB、单计划 200 行或 16 KiB、主索引历史计划 50 条、模块入口 8 项。超过只触发复核，不自动删减、拆分或覆盖内容。
- 默认读取宗旨、权威需求、索引与相关模块/当前计划；历史正文按 ID 或争议追溯。应用加载全部索引元数据及 active/paused 正文，历史正文打开时读取。总览计划数量涵盖所有索引，任务进度明确只统计 active/paused；历史任务进度在打开正文后可见。
- 监听使已加载快照失效并重读当前所需内容，不预读历史正文；编辑器脏草稿与外部变更保护保持有效。

旧索引无需修改：`| 旧计划 | done | [old](plans/old.md) |` 可直接留在 plans.md。
分层索引在 plans.md 添加 `[2026 历史计划](plans/indexes/2026.md)`，上述计划行原样移至该分片，任务文件不动。索引内任务链接统一相对 .showu，其他文档链接可相对所在文件，拒绝越界。

### 维护工具（仓库内）

- `node scripts/records.mjs audit .`：只读报告大小、入口、重复 ID、断链；不自动修复。来源计划的文字标签仍需人工核对。
- `node scripts/records.mjs split-plans . 2026`：仅当主索引超过 50 个已完成/取消计划时分片；已有同年分片需人工合并核对，不覆盖。先在 .showu-backups 下保存含所有原文和目标文本的 manifest，再写入；备份不进入默认工作区读取。
- `node scripts/records.mjs restore . .showu-backups/<批次>/manifest.json`：中断恢复；仅恢复仍等于原文或本次目标文本的文件，拒绝覆盖后续外部修改。备份保留以便追溯。
- 需求历史与计划过程按语义人工分层，不能仅凭长度自动判断有效性。迁移前记录清单/原文备份；完成后核对原文、ID、来源、链接与总数，再更新当前摘要。

### 公共工具

公共库位于应用配置目录的 shared-tools。项目指令按用户预览追加到 AGENTS.md 或 CLAUDE.md。通知与回执分别保存在 .showu/tool-inbox 和 .showu/tool-results；同一工具在单项目中至多有一份待处理通知。处理结果由项目 AI 写入，界面可刷新查看。
