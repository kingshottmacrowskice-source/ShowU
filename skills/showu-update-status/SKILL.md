# 完成状态更新（S1）

一次性查找、解释或核对信息，直接答复，不登记模块需求、计划或任务，也不更新完成状态。若用户随后明确要求修改项目或长期遵守某项约定，只对新增的项目要求执行相应流程。

完成任务或发生实质进度变化后及时更新对应 `.showu/plans/<slug>.md`。先读原文件并核对实际代码，保留其他任务与用户内容；brief 不可修改。

默认任务用 `- [ ]` / `- [x]`。进行中、受阻或取消时在下一行缩进两个空格写 `status: doing|blocked|cancelled`；恢复二态时移除覆盖行。没有运行验证的任务不能因代码写完就宣称验证通过。

记录完成内容、实际验证及结果、未验证部分、阻塞原因和下一步。改变设计时在“设计理由”追加原因、日期与影响，区分用户要求与实现判断。遇到与既有需求相斥的变化，使用 [S3](../showu-record-requirements/SKILL.md) 并停止受影响工作。

全部约定任务完成且无剩余验收条件时，将计划状态改成 done，并同步 `.showu/plans.md`；需要后续环境验证时保持 active 并写明限制。计划可 paused/cancelled，但不能把它们伪装成完成。不因时间不够就勾选完成，不删历史。

结束前检查索引、任务状态、验证证据和下一步是否相互一致，让下一次会话能直接接续。

## 规模维护

按项目文件协议的“长期规模与分层”执行；本仓库见 docs/protocol.md，初始化项目见 .showu/protocol.md。只读入口与相关当前内容，历史按需追溯；plans.md 引用的年度索引中也可能有重开的 active/paused 计划。模块代码入口只维护一份，不复制进计划。有效裁决不能藏到历史；归档保留原文、ID 和来源。相关变更结束时核对入口及链接，超过软阈值先复核，不自动删改或拆分。
