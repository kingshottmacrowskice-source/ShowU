# 需求记录与冲突检查（S3）

一次性查找、解释或核对信息，直接答复，不登记模块需求、计划或任务，也不更新完成状态。若用户随后明确要求修改项目或长期遵守某项约定，只对新增的项目要求执行相应流程。

创建计划前触发。先读用户宗旨、项目需求事实源、相关代码和 `.showu/requirements/` 中相关模块的有效需求及历史裁决，不以文件名相同替代语义比较。

对拟议需求记录模块、能力点、诉求、用户来源以及来源计划/任务。只有用户主动提出或明确确认的诉求可登记为有效需求；实现选择放计划的设计理由。

**冲突必须同时满足：同模块 + 同能力点 + 诉求相斥。** 同模块不同能力点不冲突；同能力点但可同时满足也不冲突。

存在冲突时立即停止受影响任务，不继续创建执行计划或改实现。展示旧/新诉求、各自来源、为什么无法共存以及需要用户裁决的具体问题。可在模块文件追加冲突记录，但不能把新诉求标成已生效、不能删除或覆盖旧需求。收到裁决后记下用户结论与来源，再恢复流程。

无冲突时按模块自由建立或维护 Markdown 文件，每条含稳定 ID、能力点、诉求、状态、操作（新增/变更/冲突）、来源计划/任务。变更保留原文历史，旧条目标记 superseded/deprecated，追加新条目与原因。不要按计划或流程分需求文件。

把检查过的代码、需求 ID 和结论写进计划，交 [S2](../showu-create-plan/SKILL.md) 登记计划。没有发现匹配文字不等于没有语义冲突。

## 规模维护

按项目文件协议的“长期规模与分层”执行；本仓库见 docs/protocol.md，初始化项目见 .showu/protocol.md。只读入口与相关当前内容，历史按需追溯；plans.md 引用的年度索引中也可能有重开的 active/paused 计划。模块代码入口只维护一份，不复制进计划。有效裁决不能藏到历史；归档保留原文、ID 和来源。相关变更结束时核对入口及链接，超过软阈值先复核，不自动删改或拆分。
