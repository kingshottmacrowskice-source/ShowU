## 设计理由

- Markdown 是事实源；界面从文件派生，不维护第二份任务数据库。
- 计划内保留决策、完成证据与下一步，不增加未经确认的顶层管理文件种类。
- 需求冲突是语义判断，交 S3 执行；应用不能宣称字符串匹配能完成语义审查。界面创建计划先记录检查结论。
- 保存携带读取时原文，检测外部修改后拒绝覆盖；监听只提示或刷新干净编辑器。
- 项目路径和启动命令存在应用配置目录，不污染项目仓库。
- 2026-11-04：删除计划采用归档，保留追溯所需的任务与设计理由；不删除历史需求。属于实现约定，不是新增用户需求。
- 2026-11-04：编辑器、计划表单、工具页面与公共渲染拆分成独立组件；Rust 文件存储和测试单独成模块，降低后续 AI 修改的影响范围。
- 2026-11-04：原生测试首次因缺少 Windows Common Controls 清单无法启动，已按 Tauri 上游 #13419 的处理方式为应用与测试统一嵌入清单，重跑全部通过。
- 2026-11-04：本机已安装 Rust 1.99.1、Microsoft Visual Studio 2022 C++ Build Tools；使用已有 Node.js 24.14、Git 和 WebView2。未改动用户其他项目或工具配置。
